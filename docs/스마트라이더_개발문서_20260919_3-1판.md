## 다음 세션 첫 작업: 커스텀 단축키

**준비물: `screens\RegisterScreen.js`, `screens\DetailScreen.js` 두 파일 업로드**

### 왜 1순위인가

`RegisterScreen.js` 20~21줄:

```js
const SK_SHORTCUTS       = ['SK뷰', 'SK1차', 'SK2차', 'SK3차'];                            // 동탄 전용
const SPECIAL_CHARS_MEMO = ['#', '*', '호출', '입력', '비번', '엔터', '종', '경비', '열쇠'];  // 출입정보용
```

- **`'비번'` 버튼이 그대로 있다.** "비밀번호를 적으세요"라고 앱이 직접 말하는 셈이다
- `호출`·`입력`·`엔터`·`#`·`*` 조합은 누가 봐도 현관 키패드다
- `SK...` 줄은 대표님 개인 단축키라 다른 지역 라이더에겐 쓸모가 없다
- 19줄 `SPECIAL_CHARS_NAME`(`동`, `라인`, `-`, `,`, `1,2라인`…)은 건물 이름용이라 문제없다

### 현재 구조의 불일치

| 화면 | 단축키 |
|---|---|
| `RegisterScreen.js` (새 등록 / buildingData로 열리는 수정) | 있음, 3줄 |
| `DetailScreen.js` 수정 모드 | **없음** — 입력칸만 |

### 만들 것

- **공용 부품 하나** (`screens\ShortcutBar.js` 가칭) → 등록 화면 + 상세 수정 화면 **양쪽에 끼운다**
- **탭**: 커서 위치에 글자 넣기 (지금 `insertChar`와 같은 동작)
- **길게 누르기**: 이름 바꾸기 / 삭제
- **끝에 `+` 버튼**: 새 단축키 추가
- 저장: AsyncStorage (폰에만. 서버 X)
- 기본값: **중립적인 위치 단어** — `정문` `후문` `경비실` `엘베` `계단` `주차`
- 건물 이름용 단축 줄(`SK...` 자리)도 같은 방식의 커스텀으로 — 기본값은 비워두거나 `아파트` `오피스텔` `상가`

### 대표님이 정할 것

- ⬜ 기본값에 `#`·`*`를 넣을지. 키보드 문자라 설명은 가능하지만, **빼면 방어가 더 깔끔하다.** 라이더는 필요하면 `+`로 직접 추가
- ⬜ 대표님 폰은 업데이트 후 `SK뷰`, `*`, `#` 등을 직접 다시 추가

### 타이밍

제출용 빌드는 확정이라 건드리지 않는다. **비공개 테스트 14일 동안 작업 → 정식 출시 버전에 포함.**
일반 사용자와 정식 심사가 보는 건 그 버전이다.

### 이 기능이 주는 "할 말"

> 앱이 제공하는 건 위치 메모용 빈 버튼이고, 무엇을 넣을지는 라이더가 정한다.

## 법적 우려 — 공개 문구 기조 (대표님이 다시 꺼낼 주제)

> ⚠️ 대표님이 **반드시 다시 논의하겠다**고 한 주제다. 먼저 꺼내지 말고, 꺼내면 아래에서 이어간다.
> 확정 판단은 전국 확장 전에 **변호사 상담 한 번** 권장.

### 지금까지 정리된 구조

- **앱 운영자는 가장 안전한 위치.** 출입정보를 서버로 받지 않으므로 "수집"하지 않는다. 3층 구조의 가치
- 공동현관 번호만으로는 특정 개인을 알아보기 어려워 개인정보로 보기 어렵다는 해석이 일반적.
  단, **"동·호수 + 세대 도어락 번호"**처럼 특정 가구와 묶이면 달라질 수 있다
- **라이더 쪽 현실 리스크 두 가지**
  1. **배달 플랫폼 약관** — 고객 정보를 배달 목적 외 사용·보관 금지 조항 가능성. 정확한 조항 확인 필요
  2. **입주민 민원** — 법 문제가 없어도 "비번 DB 돌린다" 소문 한 번에 앱 이미지가 끝난다

### 기조 (09-19 합의)

| | 내용 | 쓰는 곳 |
|---|---|---|
| **1번 기조** | "자주 가는 건물의 **메모**"라고만 말한다. 비밀번호 저장을 권하지 않는다. 라이더가 적는 건 그 사람의 메모 | **모든 공개 문구** (스토어, 소개 페이지, 앱 안내) |
| 2번 기조 | "고객이 알려준 번호를 기억하는 것과 뭐가 다른가. 불안하면 바꾸는 게 맞다" | **분쟁 시 대응 논리로만.** 공개하면 입주민을 적으로 돌린다 |

- ⬜ 이용약관에 "저장한 내용의 관리 책임은 본인에게 있으며, 배달 목적 외 사용·공유를 금지한다" 추가 검토
- ⬜ 앱 안 안내·예시 문구에서 "비밀번호" 단어 점검 (단축키가 1차 대상)

### 상태

- ✅ `D:\app\richcanopy\app\smartrider\page.js` 작성, 로컬 확인 완료
  - 캐노피 메뉴 안 보임 / 이미지 자리 4곳 / 하단 다운로드 버튼 고정 / FAQ 펼침 / 캐노피 푸터 안 보임 — 전부 정상

### ⬜ 문구를 1번 기조로 다시 써야 한다

지금 페이지는 **"비번"이 전면에** 있다. 법적 우려 논의 후 아래 방향으로 교체:

| 지금 | 바꿀 방향 |
|---|---|
| 현관 앞에서 비번 찾지 마세요 | 한 번 간 건물, 다음엔 헤매지 마세요 |
| 토스트 그림 `1234*` | "후문 계단이 빨라요 / 경비실은 정문 왼쪽" 같은 메모 |
| 공감: "요청사항 다시 열어 비번 찾기" | "동 입구가 어디였더라", "주차는 어디에 했더라" |
| 비번은 서버에 없습니다 | 내 메모는 서버에 없습니다 |
| FAQ: 비번이 새어나갈 걱정은? | 내 메모, 다른 사람이 볼 수 있나요? |

### ⬜ 대표님 확인 필요

- FAQ **배터리** 답 — 코드에 `⚠️` 표시. 실사용 경험으로 채울 것
- **"선착순 200명 평생무료"** — 페이지에 약속으로 박힌다. 확정 여부
- "앱 안에 광고가 나올 수 있다 / 달리는 중 화면엔 없음" — 솔직하게 넣어둠

### 채실장 이미지 주문서 (4장 + 선택 1장)

| # | 내용 |
|---|---|
| 2 | 토스트 확대: 건물 이름 + 메모 줄 |
| 3 | 상세 화면: 동 배치도 |
| 4 | 후면 단속 구간 안전 알림 |
| 5 | 폰 + 자물쇠, "서버에 저장 안 함" |
| 선택 | 카톡 공유 미리보기 가로 이미지 **1200×630** |

- 세로 **1080×1350**, 한 장 **300KB 이하**
- **배민·쿠팡 로고·화면 절대 금지** (상표). "배달앱"은 흐리게
- 단속은 "안전운전 알림" 톤
- 메모 예시는 전부 명백한 가짜. **1번 기조에 맞춰 비번보다 위치 메모 위주로**
- ⚠️ 앱 캡처는 **심사용 테스트 계정 + 가짜 건물**로. 대표님 실제 969건이 찍히면 안 된다

### 명함 문구 (안)

- 앞면: 로고 + "건물이 먼저 알려주는 라이더 앱"
- 뒷면: 도착하면 내 메모 자동 표시 / 후면 단속 안전 알림 / 내 메모는 내 폰에만 + 선착순 200명 평생무료 + QR
- QR에 `?from=이름`을 붙여 스텝별 성과 확인하는 방법도 있음 (선택)

## 3판 "바로 이어서 할 것" 갱신

```
1. versionCode 1 → 2
2. Play Console 양식 (앱 액세스 / 광고 / 데이터 보안 / 위치 선언 / 스토어 설명 — 1번 기조로)
3. USE_TEST_ADS = false → bundleRelease → 배포보관 → 제출 → true로 복귀
4. 비공개 테스트 14일 동안:
   ① 커스텀 단축키  ← 최우선 (RegisterScreen + DetailScreen)
   ② 소개 페이지 문구 1번 기조로 교체 → 채실장 이미지 → 배포
   ③ memo2 싱크, Promise.all 분리, 알림지점 필터 제거, 피쉬라인 애드몹
5. 정식 출시 → 명함 배포 시작
```
