### ★★ 09-19 — 서비스가 JS에 말을 걸 때는 `reactHost`를 쓴다

코틀린 **서비스**는 JS와 직접 연결되어 있지 않아서, 이벤트를 보낼 때 "지금 떠 있는 RN"을 찾아야 한다.

```kotlin
// ❌ 구 아키텍처 방식 — 새 아키텍처에서는 조용히 null이 된다 (에러도 안 난다)
(application as? ReactApplication)
    ?.reactNativeHost
    ?.reactInstanceManager
    ?.currentReactContext

// ✅ 새 아키텍처 방식 — MainApplication.kt에 reactHost가 이미 만들어져 있다
(application as? ReactApplication)
    ?.reactHost
    ?.currentReactContext
```

**09-19에 고친 4군데** (`ProximityOverlayService.kt`):

| 함수 | 이벤트 이름 | 깨졌을 때 증상 |
|---|---|---|
| `emitMuteCount` | `ProximityMuteCount` | 설정 → 안보기 지점 "확인 중..."에서 멈춤 |
| `emitOpenHome` | `ProximityOpenHome` | 플로팅버튼 → 홈 열기 안 됨 |
| `emitOpenMap` | `ProximityOpenMap` | 플로팅버튼 → 지도 열기 안 됨 |
| `emitDetailRequest` | `ProximityToastDetailRequested` | 토스트 더블탭 → 상세 안 감. 로그에 `상세 요청 보류 — JS 아직 준비 안 됨` 반복 |

**확인 명령:**
```
findstr /n "reactInstanceManager" ProximityOverlayService.kt
```
**아무것도 안 나와야 정상.**

> 앞으로 서비스에서 JS로 이벤트를 보내는 함수를 새로 만들면 **반드시 `reactHost` 방식으로.**
> 모듈(`ProximityOverlayModule.kt`)의 `@ReactMethod`는 호환 모드로 잘 돌아서 손댈 필요 없다.
> 문제는 **코틀린이 먼저 JS에 말을 거는 방향**뿐이다.

### ★★ 09-17 최대 사고 — 포그라운드 서비스(FGS) 지뢰

**앱이 네 번 죽었다. 전부 같은 원인이었고, 두 번은 잘못된 처방 때문에 더 죽었다.**

에러 메시지 두 종류:

```
① java.lang.SecurityException: Starting FGS with type location
     requires permissions [ACCESS_COARSE_LOCATION, ACCESS_FINE_LOCATION]
     at ProximityOverlayService.onCreate(...)

② ForegroundServiceDidNotStartInTimeException:
     Context.startForegroundService() did not then call Service.startForeground()
     at ProximityOverlayModule.send(...)
```

**규칙 전체:**

1. `startForeground()`에 `FOREGROUND_SERVICE_TYPE_LOCATION`을 선언했으면,
   **위치 권한이 없을 때 그 호출 자체가 SecurityException으로 프로세스를 죽인다.** (targetSdk 34+)
2. `startForegroundService()`로 서비스를 띄운 이상,
   그 서비스는 **5초 안에 반드시 `startForeground()`를 한 번은 불러야 한다.**
3. **`stopSelf()`로 조용히 빠져나가는 것도 "약속 어김"으로 처리되어 똑같이 죽는다.**

**결론: 서비스 안에서 막을 수 없다. 호출부(모듈)에서 아예 인텐트를 안 보내야 한다.**

```
❌ 서비스 onCreate/onStartCommand에서 stopSelf() → 여전히 죽음
✅ ProximityOverlayModule의 각 @ReactMethod에서 권한 없으면 return
```

`ProximityOverlayModule.kt`의 `hasLocationPermission()`이 그 관문이다.
서비스 쪽 관문 2개(`onCreate`, `onStartCommand`)는 **안전망으로 남겨뒀다. 지우지 말 것.**

> 앞으로 `ProximityOverlayModule.kt`에 서비스를 시작하는 메서드를 새로 추가하면
> **반드시 `hasLocationPermission()` 검사를 함께 넣는다.**
> 단, `hasPermission` / `requestPermission` / `stopService` 3개는 예외 — 서비스를 켜지 않는다.

### ★ 09-17 — 권한 요청은 PermissionScreen이 전담한다

구글 백그라운드 위치 심사의 핵심은 **"설명이 요청보다 먼저"** 다.

```
❌ 로그인 → 시스템 팝업 3연발 → (뒤늦게) 권한 안내 화면
✅ 로그인 → 권한 안내 화면(설명) → 사용자가 버튼을 누를 때만 팝업
```

| 위치 | 하는 일 |
|---|---|
| `PermissionScreen.js` | **요청** (`request...`) — 여기서만 |
| `ProximityNotifier.js` | **확인만** (`get...`) — 없으면 조용히 물러남 |
| `PermissionScreen.done()` | 권한 받은 뒤 `startService()` 호출 |

> `setup()`은 `setupDone` 전역 플래그 때문에 **앱 실행당 1회**만 돈다.
> 그 공백을 `PermissionScreen.done()`이 메운다. 이 연결을 끊지 말 것.

`ProximityNotifier`의 `AppState` 리스너에도 권한 검사가 들어 있다.

### `Promise.all` 지뢰 (09-16)

`Promise.all`은 **하나만 실패해도 전부 버린다.** 홈 화면에서 건물과 알림을 묶었다가
알림 쪽이 터지면서 **건물 969건이 화면에서 통째로 사라졌다.**

**규칙: 본체와 곁다리는 `try`를 따로 감싼다.** 오류 팝업에는 **반드시 `e.message`를 붙인다.**

```js
try {
  const list = await getCachedBuildings(isRefresh);
  setBuildings(...);
} catch (e) {
  Alert.alert('오류', '건물 데이터를 불러오지 못했습니다.\n' + (e?.message || ''));
}

try {
  const aList = await getAllAlertPoints();
  setAlerts(...);
} catch (e) {
  setAlerts([]);
  console.log('알림지점 로드 실패:', e?.message);
}
```

> ⚠️ `buildingsCache.js`의 `getCachedBuildings()` 안에도 같은 `Promise.all`이 남아 있다.
> 아직 안 고쳤다. 11장 미해결 참조.

### 반대 방향의 지뢰 — catch가 아예 없는 곳 (09-17)

권한 확인 같은 시스템 호출은 권한 상태에 따라 throw할 수 있으므로 **항상 `try`로 감싼다.**

### "코드는 줬는데 붙여넣어지지 않은 줄" (09-16, 09-17 재발)

**규칙 둘:**
1. 붙여넣을 코드에 새 줄 표시를 단다 (`// ★ 새 줄`)
2. **JSX 문법 오류는 에러가 난 줄이 아니라 그 위를 본다.**
   VSCode **문제 탭(`Ctrl+Shift+M`)**에서 **첫 번째 에러의 줄·칸 번호**만 보면 된다.

> **JSX 안에서는 `// ★` 주석을 붙여넣지 않는다.** 화면에 글자로 나오거나 문법 오류가 된다.
> JSON(`app.json`)에도 주석을 넣으면 안 된다.

### JSX 안에서 위험한 문자 (09-17)

`>` `<` `{` `}` 가 텍스트로 들어가면 파서가 태그로 오해한다.
`→` `☰` `—` 같은 특수문자도 환경에 따라 말썽이다. **안전한 쪽: 특수문자를 아예 쓰지 않는다.**

```jsx
❌ 개인정보처리방침 →
✅ {'개인정보처리방침 →'}
```

### 에러 대응 순서

1. **앱이 죽는다 (FATAL EXCEPTION)** → 0장 FGS 지뢰부터 의심.
   `adb logcat -d AndroidRuntime:E ReactNativeJS:E PROX_KT:D *:S > D:\crash.txt` → **`Caused by:` 줄**
2. **`ReferenceError: Property 'xxxx' doesn't exist`** → `xxxx` 전체 검색. 대개 **import가 없다**
3. **새 기능이 조용히 0/빈 화면** → `try/catch`가 삼키고 있다. `adb logcat ReactNativeJS:V *:S`
4. **설정이 안 먹음** → `app.json` 말고 `android/` 안을 본다 (단, 광고 앱 ID는 예외 — 1장)
5. **JSX 문법 오류** → 첫 에러의 줄 번호, 그 **위**를 본다
6. 빌드 실패 → 파일 잠김 의심 → `gradlew --stop` → 탐색기/스튜디오 닫기 → `clean`
7. **`Duplicate resources`** → 같은 이름의 `.png`와 `.webp` 공존. 옛 `.webp` 삭제
8. **`native crypto module could not be used...`** → `react-native-get-random-values` import 순서
9. 데이터가 안 보임 → 보안 규칙부터 의심
10. 토스트가 안 뜸 → **권한 3종부터 확인**
11. **`adb`가 `waiting for device`** → `adb kill-server` 후 `adb devices`. USB 모드 "파일 전송" 확인
12. **`Cannot access 'NativeAppModuleSpec'`** (09-19) → `newArchEnabled`가 `false`다
13. **코틀린 로그에 "JS 아직 준비 안 됨" 반복 / 설정 "확인 중..." 멈춤** (09-19) → 서비스가 `reactInstanceManager`를 쓰고 있다. `reactHost`로
14. **`Task 'install' is ambiguous`** (09-19) → 명령 두 줄이 붙었다

### ★ `app.json`은 안드로이드에 반영되지 않는다 — 예외 1개

`android/` 폴더가 이미 있는 bare workflow이므로 **`app.json`의 값은 실제 빌드에 쓰이지 않는다.**

```
android/app/src/main/res/values/strings.xml
  <string name="app_name">스마트라이더</string>   ← 이게 화면에 뜨는 이름
```

아이콘(`res/mipmap-*`), 권한(`AndroidManifest.xml`), 패키지명(`build.gradle`)도 전부 `android/` 안이 진짜다.

**예외 (09-19): 광고 앱 ID.** `react-native-google-mobile-ads`는 **빌드할 때 gradle이 `app.json`을 직접 읽는다.**
prebuild와 무관하게 동작한다. 1장 참조.

## 5장. 계정 삭제 (09-17)

구글 플레이는 로그인이 있는 앱에 **앱 내 계정 삭제 경로**를 요구한다.

### 삭제 순서 — 역순이 중요하다

```
1. reauthenticateWithCredential()   ← 비밀번호 재확인. 실패하면 중단
2. Storage  suggestions/{uid}/ 사진 삭제
3. DB       내 제보 글 삭제
4. DB       users/{uid} 삭제
5. (선택)   폰 AsyncStorage 건물·메모·즐겨찾기 삭제
6. deleteUser()                     ← 반드시 마지막
```

**계정을 먼저 지우면 권한이 사라져 나머지를 못 지운다.**

> ⚠️ 09-17 이전에 올린 제보는 id 기록이 없어 남는다. 어드민이 콘솔에서 직접 지운다.

### 보안 규칙 변경 2건 (09-17)

- RTDB `suggestions/$id` `.write`: `+ data.child('uid').val() === auth.uid`
- Storage `suggestions/{uid}/`: `allow delete: if isSignedIn() && (request.auth.uid == uid || isAdmin());`

> Storage에서 `allow delete`를 따로 쓰면 `write`보다 **그게 우선한다.**

## 6장. 백업

### 구조

사용자가 정한 비밀번호로 **AES-256-CBC 암호화.** 열쇠는 PBKDF2(SHA-256, 10,000회)로 비밀번호에서 만든다.
**폰이나 서버에 열쇠를 저장하지 않는다.** 비밀번호를 잊으면 제작자도 못 연다.

```json
{
  "format": "smartrider-backup-enc",
  "v": 1, "alg": "AES-256-CBC", "iter": 10000,
  "salt": "...", "iv": "...",
  "exportedAt": "...",
  "counts": { "buildings": 1092, "notes": 7, "favorites": 7 },
  "data": "(암호문)"
}
```

- 겉면(개수·날짜)은 일부러 암호화하지 않는다 (복원 화면에서 최신 파일 고르기용)
- 평문 앞 `SRB1` 도장으로 복호화 후 비밀번호 검증
- 확장자 `.json` 유지 (낯선 확장자는 카톡이 막는 경우가 있다)

### ✅ 경고 문구 — 09-19 재검토 결과 "현재로 충분"

2판에는 "경고 강화 + 동의 체크박스 ⬜"로 적혀 있었다. 09-19에 `Sidebar.js`를 열어보니 이미 이렇게 되어 있었다:

- 백업 창 설명: "이 파일에는 출입 비밀번호가 들어 있습니다. 카톡이나 메일로 보내도 안전하도록 잠급니다"
- 경고 박스: "비밀번호를 잊으면 복원할 수 없습니다. 만든 사람도 열 수 없습니다"
- 메뉴 아래 안내: "내 폰에만 있는 데이터입니다. 백업 파일은 비밀번호로 잠기므로 카톡·메일로 보내도 남이 열 수 없습니다"

**암호화가 체크박스보다 강한 방어**라 출시 항목에서 뺐다.

> **선택 사항으로 남겨둔 것 (출시 후 필요하면):** 2판에서 설계한 강한 문구 —
> "비밀번호가 짧거나 파일과 비밀번호를 함께 전달하면 누구나 열 수 있다 /
> 유출·공유로 발생하는 책임은 본인이 부담" + 매번 체크하는 동의 체크박스 +
> "영문+숫자+기호 10자 이상 권장". 민원이나 사고가 생기면 그때 넣는다.
> 구현은 `DeleteAccountScreen.js`의 `Check` 컴포넌트를 참고.

### 비밀번호 규칙

`validatePassword()` — 영문 1개 + 숫자 1개 + 8자 이상, 공백 불가.
**비밀번호 길이가 유일한 방어선이다.** (숫자 6자리: 몇 초 / 영문+숫자 8자: 며칠~몇 달 / 영문+숫자+기호 10자: 수백 년)

### 분실 대응

**메뉴 → 백업 비밀번호 다시 보기** — `expo-secure-store`에서 꺼내 보여준다.
