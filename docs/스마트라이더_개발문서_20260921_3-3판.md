## 6장. 테스트 14일 동안 할 코드 작업 — 순서대로

### ① `Promise.all` 분리 — 제일 작고 제일 급함
📁 `buildingsCache.js` → **다음 세션 첫 작업. 이 파일 하나만 올리면 된다**

- `getCachedBuildings()`가 **공용 건물(서버) + 내 건물(폰)**을 `Promise.all`로 같이 부른다
- `Promise.all` = 하나라도 실패하면 **전부 버림**
- 인터넷이 잠깐 끊겨 공용만 실패해도 **폰에 멀쩡한 969건까지 화면에서 사라진다** (09-16 홈 화면에서 실제 사고)
- 해결: 둘을 **따로 `try`로** 감싼다. 공용이 실패해도 내 건물은 보이게
- 규칙: 오류 팝업엔 반드시 `e.message`

### ② memo2 싱크 — 등록한 게 바로 안 뜸
📁 `RegisterScreen.js`, `DetailScreen.js`

- 저장해도 토스트에 바로 반영 안 됨. 앱을 내렸다 다시 열면 뜬다
- 원인: 토스트는 **코틀린**이 띄우는데, 저장 후 코틀린에 목록을 **다시 넘기지 않아서**
- 해결: 저장 직후 `syncBuildings()` 류 **한 줄**
- 라이더가 등록하고 바로 다시 갔는데 안 뜨면 "고장"으로 느낀다 → 체감 큼

### ③ 강력알림 버전 캐시 — 서울청 데이터 들어오기 전 필수
📁 `firebaseDB.js`, `alertSync.js`, Firebase 보안 규칙

- 지금은 홈·지도·설정을 열 때마다 **전국 지점을 처음부터 다시 받는다** (캐시 없음)
- 40개일 땐 괜찮지만 1,000개 × 200명 × 하루 10번 ≈ 월 6GB → 무료 한도(약 10GB) 근접
- 해결:
  ```
  서버: meta/alertsVersion = 타임스탬프   ← 지점 추가·수정·삭제 때 갱신
  앱:   버전 숫자만 확인 → 같으면 폰에 저장된 것 / 다르면 그때만 전체 다운로드
  ```
- 덤: 인터넷이 끊겨도 폰에 저장된 지점으로 경고
- 보안 규칙에 `meta` 노드 추가 (읽기: 로그인 / 쓰기: 어드민). 지금은 `$other`가 막고 있다
- 같이 볼 것: 코틀린 전달 크기 **약 1MB 제한**. 지점 수천 개부터 위험 → 내 주변 N km만 넘기기 or 지역 분리
- 알림 지점 자체는 Firebase라 **앱 업데이트 없이** 반영된다. 서울청 회신 오면 엑셀 → Firebase 일괄 입력 스크립트만

- **"평생무료" 약속은 모든 공개 자료에서 금지** — 소개 페이지·명함 전부 제거 완료
- 공개 문구는 "지금은 전부 무료 / 추후 월 구독 예정 / 먼저 시작한 분께 무료 기간"까지만
- 가치 논리: 모두의 편의가 아니라 **개인 라이더의 경쟁력.** 300~400건 쌓이면 효과가 난다
- 유료화는 **라이더가 가치를 느낀 뒤** (정식 출시 후)
