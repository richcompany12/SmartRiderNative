
## 2장. ShortcutBar (커스텀 단축키)

```
screens/ShortcutBar.js
  props: storageKey, onPick(label)
  탭: onPick / 길게: 이름 바꾸기·삭제 모달 / +: 추가
  기본값: ['길게', '눌러', '수정']   ← 버튼 자체가 사용법 안내
  최대 12개, 10자, AsyncStorage에만 저장
```

| storageKey | 쓰는 곳 |
|---|---|
| `shortcuts_name` | 등록(건물 이름) · 상세 수정(건물 이름) · **검색 화면 단축 검색어** |
| `shortcuts_memo` | 등록(도착 메모) · 상세 수정(도착 메모) |

- 같은 key를 쓰는 화면끼리는 즉시 동기화된다 (모듈 안 listeners)
- **이름 버튼 = 검색 버튼**. `SK뷰`를 한 번 만들면 등록·검색 양쪽에서 쓴다
- 삭제된 것: `SPECIAL_CHARS_NAME`(동·라인), `SK_SHORTCUTS`, `SPECIAL_CHARS_MEMO`(`비번` 포함)

**왜 바꿨나**: 기본 단축키에 `비번`·`호출`·`엔터`·`#`·`*`가 있어 "비밀번호를 적으세요"라고 앱이 권하는 꼴이었다. 이제 **무엇을 적을지는 라이더가 정한다.** (3-1판 법적 기조)

`RegisterScreen`: `insertChar` → `insertTo(field, ch)` / `DetailScreen`: `memoField` state(**로딩 return보다 위, 197줄 근처**) + `append(k, ch, max)`

## 3장. 검색 개선

```js
tokenize: 띄어쓰기 + 글자↔숫자 경계에서 자름 → clean → 빈 것 제거
matchToken: 숫자 조각 = 이름 속 숫자에 포함 / 글자 조각 = 이름 포함 or 초성 포함
결과: 모든 조각이 맞는 건물만 (AND)
index: 건물별 clean·초성·숫자를 미리 계산 (useMemo)
useDeferredValue(term): 한글 입력 버벅임 완화
```

- "포스코 푸른마을"(순서 반대), "ㅍㄹㅍㅅㅋ0512"(붙여쓰기) 모두 찾는다
- 예전 "ㅍㄹㅍㅅㅋ 0512"가 잘 됐던 건 사실 **숫자만으로** 찾고 있었기 때문
- 부작용: 조각 하나라도 틀리면 안 나온다 (예전보다 정확하지만 엄격)
- ⬜ 업데이트 후에도 "정확히 쳤는데 안 나오는" 이름이 있으면 **건물 이름 + 친 글자**를 기록해서 확인

## 6장. 유료화 설계 (09-20 결정)

### 핵심 논리 (대표님)

이 앱의 가치는 **"남보다 빠르다"는 상대적 우위**다. 모두가 쓰면 우위가 사라지고 플랫폼도 반응한다.
**구독료는 수익 이전에 가치를 지키는 울타리.** 고인물이 대단해 보여야 앱이 빛난다.
대표님 경험: 1,000개 모으는 데 3년, **300~400개부터 토스트가 제대로 빛을 발한다.**

### 결정

- **토스트 = 유료 (월 약 5천원)**
- 초기 가입자 **100~200명**: **6개월 또는 1년 무료 → 이후 유료 전환** (인원·기간 미정)
- **"평생무료" 약속은 하지 않는다** → 소개 페이지·명함·스토어에서 제거
- 유료 전환 예정이라는 걸 **가입 때부터 알린다** (몰랐던 사람이 화낸다)
- **무료로도 데이터는 절대 잠그지 않는다** (등록·목록·검색·상세·복사·로컬 백업은 무료) — 처음부터 명확한 상품이면 인질 프레임이 아니다
- 보안·공유 방지: **현 상태 유지.** 앱은 충분히 경고·암호화했다. 계정 공유·노가다 복사까지는 막지 않는다

### 구조 (나중에 만들 때)

```
users/{uid}/plan       'free' | 'founder' | 'pro'
users/{uid}/planUntil  만료일
users/{uid}/stats/buildingCount  ← 개수만. 내용 X (처리방침·데이터 보안에 추가 필요)
```
- 토스트 대상 여부는 JS에서 판단 → 대상 아니면 건물 목록을 코틀린에 안 넘김
- **보안 규칙: `plan`은 어드민만 쓰기** ⚠️ (안 막으면 사용자가 자기 plan을 pro로 바꿀 수 있다)
- 지인 무료 지정: Firebase 콘솔에서 `plan` 직접 수정 (나중엔 어드민 화면)
- **초기 N명 선별: Firebase 인증의 가입 시각** 기준 (지금 따로 셀 필요 없음). 심사 계정·대표님 계정·탈퇴 테스트 계정 제외
- 결제: 구글 플레이 결제 필수 → **RevenueCat** 검토 (도입 전 새 아키텍처 호환 확인)
- 유도 팝업: `backup.js`의 `checkBackupNudge(건물수)` 활용. 50·100·200개 구간마다 1회, **홈에서만**, 보호 프레임
- 구독 붙이면: 콘텐츠 등급 설문 "디지털 상품 구매" → **예**로 재제출 / pro는 광고 제거

### 참고: 공유를 더 막고 싶어질 때 (지금은 안 함)

- 한 계정 한 기기 (새 기기 로그인 시 기존 기기 로그아웃)
- 폰 데이터에 주인 uid 기록 → 다른 계정 로그인 시 안 보이게 (969건 저장 구조를 건드리므로 백업 후 별도 세션)
- 백업 파일에 계정 새기기 → 다른 계정 복원 불가

## 7장. 강력알림 대량 투입 전 필수 작업

### 알림 지점은 앱 업데이트가 필요 없다

`alerts`는 Firebase에 있다. 어드민이 등록하면 **즉시 모든 사용자에게 반영**. 심사와 무관.
서울청 회신 오면 엑셀 → Firebase **일괄 입력 스크립트**만 만들면 된다.

### ⚠️ 그 전에 할 것 (같은 파일들이라 한 번에)

**① 버전 기반 캐시** — 지금 `alerts`는 **캐시가 없어** 홈·지도·설정을 열 때마다 전국을 다시 받는다
```
meta/alertsVersion = 타임스탬프    ← 지점 추가·수정·삭제 시 갱신
앱: 버전 숫자만 확인 → 같으면 폰에 저장된 것 사용 / 다르면 그때만 전체 다운로드
```
- 1,000개 × 라이더 200명 × 하루 10번 ≈ 월 6GB → Firebase 무료 한도(약 10GB) 근접. 버전 캐시로 수백 분의 1
- 덤: 인터넷이 끊겨도 폰에 저장된 지점으로 경고
- 보안 규칙에 `meta` 노드 추가 필요 (읽기: 로그인 / 쓰기: 어드민). `$other`가 막고 있다
- 공용 건물도 나중에 같은 방식 가능 (지금은 3시간 캐시 유지)

**② 코틀린 전달 크기 제한** — JSON 한 덩어리를 인텐트로 넘기는데 **약 1MB 제한**. 지점 1개 ≈ 100자 → **수천 개부터 위험**
- 해법: 내 위치 주변 N km만 골라 넘기기 or `cameras/{시도}/{시군구}` 지역 분리 (3판 12장)
- 서울 데이터 실제 개수 보고 결정

파일: `firebaseDB.js`, `alertSync.js`, 보안 규칙

## 8장. 토스트 지연 (S26 울트라에서 간헐적)

**앱이 무거워서가 아닐 가능성이 크다**
- 거리 계산은 구형 폰에서도 수 ms. 지점이 수천 개로 늘어도 계산 때문엔 안 느려진다
- **설계상 대기**: 반경 20m 안에서 **5초 체류** + 위치 3초 간격 → 실제 5~8초. 아파트 사이는 GPS가 튀어 진입 인식 자체가 늦을 수 있다
- 다른 앱을 닫았더니 좋아진 건 **삼성 배터리 관리**가 위치 업데이트 간격을 늘렸을 가능성

**대응**
- ⬜ 테스터 안내문에 추가: `설정 → 애플리케이션 → 스마트라이더 → 배터리 → "제한 없음"`
- ⬜ (나중) 권한 안내 화면에 4번째 항목으로
- 재발 시 로그: `adb logcat PROX_KT:D *:S` → `위치 ...` 줄이 **3초 간격**인지. 10초 이상 벌어지면 시스템이 조인 것
